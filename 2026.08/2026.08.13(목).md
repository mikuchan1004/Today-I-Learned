## FastAPI 라우팅

> 아래의 내용들은 Google Gemini의 도움을 받아 작성하였음을 밝힙니다.

### 라우팅 

손님이 찾아온 주소(URL)와 행동(HTTP Method)에 따라 적절한 방(함수)으로 안내하는 것.

클라이언트가 특정 URL로 요청을 보내면, FastAPI는 설정된 라우트를 확인하고 해당하는 Python 함수를 실행해 결과를 반환한다.

### 기본 라우트 만들기 

FastAPI에서는 데코레이터(`@app.get`, `@app.post`등)를 사용해서 경로와 HTTP 메서드를 정의한다.

``` python
from fastapi import APIRouter, Form, Request

todo_router = APIRouter()

todo_list = []

@todo_router.post("/todo")
async def add_todo(todo:dict) -> dict:
    print('todo:', todo)
    todo_list.append(todo)
    return{
        "message" : "정상적으로 추가되었습니다."
    }

@todo_router.get("/todo")
async def retrieve_todos() -> dict:
    return {
        "todos": todo_list
    }


@todo_router.get("/todo/param")
async def todoParamGet(id : int, item:str = "") -> dict:
    print(id, item)
    return {
        "id": id,
        "item" : item
    }

@todo_router.post("/todo/param")
async def todoParamPost(id : int = Form(), item:str = Form()) -> dict:
    print(id, item)
    return {
        "id": id,
        "item" : item
    }

@todo_router.get("/todo/param2")
@todo_router.post("/todo/param2")
@todo_router.put("/todo/param2")
@todo_router.delete("/todo/param2")
async def todoParam(req:Request) -> dict:
    if req.method == "GET":
        data = req.query_params
    else :
        data = await req.form()

    id = data.get('id')
    item = data.get('item')
    print(id, item, req.method)

    return {
        "id": id,
        "item" : item
    }

print(2, __name__)

if __name__ == "__main__":
    print('todo.py 파일 직접 실행')
```

**자주 쓰이는 HTTP 메서드 4가지**

|메서드|역할|예시|
|:---|:---|:---|
|**GET**|데이터 **조회**|게시글 목록 읽기, 프로필 보기|
|**POST**|새로운 데이터 **생성**|회원가입, 글 작성|
|**PUT**|기존 데이터 **전체 수정**|프로필 정보 전체 업데이트|
|**DELETE**|데이터 **삭제**|계정 탈퇴, 게시글 삭제|

### 파라미터 전달 방식 (경로 vs 쿼리)

사용자에게 값을 전달받는 방식은 크게 경로 파라미터(Path Parameter)와 **쿼리 파라미터(Query Parameter)** 두 가지가 있다.

**1. 경로 파라미터(Path Parameter)** 

URL 경로의 일부로 데이터를 받는 방식. **특정 대상을 유일하게 식별할 때** 주로 사용.

``` python
@app.get("/items/{item_id}")
def read_item(item_id: int): # int 타입으로 자동 변환 및 검증!
    return {"item_id": item_id}
```

* **요청 URL** : `/items/42`
  
* **결과** : `item_id`는 숫자 `42`가 된다.

**2. 쿼리 파라미터(Query Parameter)** 

URL 뒤에 `?key=value` 형태로 붙여 전달하는 방식. **정렬, 검색, 페이징 등 옵션을 줄 때** 사용.

``` python
@app.get("/items/")
def read_items(skip: int = 0, limit: int = 10):
    return {"skip": skip, "limit": limit}
```

* **요청 URL** : `/items/?skip=20&limit=5`

* **결과** : `skip=20`, `limit=5`가 적용된다. (값을 안 넣으면 기본값 `0`, `10`이 들어간다)

**한 눈에 비교하기**

|구분|위치|주요 용도|예시 URL|
|:---|:---|:---|:---|
|**Path Parameter**|URL 경로 자체(`/users/{id}`)|특정 자원 식별 (필수)|`/users/12`|
|**Query Parameter**|URL 뒤의 `?` 파트(`users?limit=5`)|필터링, 정렬, 옵션(선택)|`search?q=fastapi`|

### 코드가 길어진다면? APIRouter로 분리하자!

모든 라우트를 파일 하나에 다 때려넣으면 코드가 지저분해지기 때문에 `APIRouter`를 사용해서 기능별로 파일을 깔끔하게 나눠야 한다. 

**1단계. 기능별 파일 작성(`routers/users.py`)**

``` python

from fastapi import APIRouter

# app 대신 router 객체를 생성합니다.
router = APIRouter(
    prefix="/users",
    tags=["Users"] # Swagger 문서에서 그룹화되어 보기 편해져요!
)

@router.get("/")
def get_users():
    return [{"username": "admin"}, {"username": "user"}]

@router.get("/{user_id}")
def get_user(user_id: int):
    return {"user_id": user_id}
```

**2단계. 메인 앱에 등록(`main.py`)**

``` python
from fastapi import FastAPI
from routers import users # 위에서 만든 루터 가져오기

app = FastAPI()

# 라우터 포함시키기
app.include_router(users.router)
```

이렇게 해두면 `main.py`는 깔끔하게 유지되고, 회원 관련 라우트는 `/users`라는 접두어(prefix)를 달고 자동으로 깔끔하게 정리된다.

### 접두어(Prefix)

반복되는 주소의 앞부분을 한 번에 묶어주는 대문!

만약 회원 관련과 관련된 API 라우트를 만든다고 했을때. 접두어가 없다면 매번 경로마다 `/users`를 일일히 써주어야 한다. 

**접두어가 없을 때**

``` python
router = APIRouter()

@router.get("/users")              # /users
def get_users(): ...

@router.get("/users/{user_id}")     # 또 /users...
def get_user(user_id: int): ...

@router.post("/users")             # 또 또 /users...
def create_user(): ...
```

**접두어(Prefix)를 쓸 때**

``` python
# prefix="/users"를 지정하면 하위 라우트에 자동으로 붙습니다!
router = APIRouter(prefix="/users")

@router.get("/")        # 실제 요청 주소: GET /users/
def get_users(): ...

@router.get("/{user_id}") # 실제 요청 주소: GET /users/12
def get_user(user_id: int): ...

@router.post("/")       # 실제 요청 주소: POST /users/
def create_user(): ...
```

**접두어를 쓰는 이유**

* **중복 제거** : `/users`나 `/api/v1` 같은 공통 경로를 일일히 입력할 필요가 없다.

* **유지보수 용이** : 나중에 회원 관련 주소 기본값을 `/members`로 바꾸고 싶을 때, `prefix` 한 곳만 수정하면 끝!

### 스웨거 문서(Swagger Documentation)

스웨거(Swagger)는 백엔드 개발자가 만든 API 목록을 프론트엔드 개발자나 다른 사람이 한눈에 보고 직접 테스트할 수 있도록 만든 대화형 API 명세서.

원래는 이 문서를 작성하려면 개발자가 손수로 JSON이나 YAML 코드를 써서 만들어야 했었지만... 

**FastAPI는 코드를 작성하기만 하면 스웨거 문서를 100% 자동으로 만들어준다!**

**스웨거 문서 확인 방법**

FastAPI 서버를 실행한 뒤, 브라우저 주소창 뒤에 `/docs`만 붙이면 바로 열린다. 

``` text
http://localhost:8000/docs
```

**스웨거 문서의 핵심 매력 3가지**

* **자동 시각화(Auto-Documentation)**

  * `@router.get("/users")`같은 코드와 Python 타입 힌트(`user_id: int`)를 분석해서 알아서 예쁜 대시보드로 만들어 준다.
 
* **즉시 웹 테스트(Try it Out)**

  * Postman 같은 별도의 프로그램 없이, 브라우저 화면에서 바로 **'Try it out'** 버튼을 눌러 데이터를 넣어보고 API 요청을 테스트해 볼 수 있다.
 
* **태그(Tags)를 통한 그룹화**

  * 라우터 설정할 때 넣었던 `tags=["Users"]` 덕분에, 스웨거 문서 화면에서 회원 관련 API, 상품 관련 API가 깔끔하게 카테고리별로 접혀서 보인다.
 
**한눈에 정리하기**

|개념|역할|한 줄 요약|
|:---|:---|:---|
|**Prefix(접두어)**|URL 주소 구조화|공통 주소를 묶어 코드를 깔끔하게 만듦(`/users/...`)|
|**Swagger UI(`/docs`)**|API 명세 및 테스트|내가 만든 API를 웹에서 자동으로 보여주고 테스트하게 해줌|
